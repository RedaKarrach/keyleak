incident response for a leaked AWS access key · MIT · github.com/RedaKarrach/keyleak

What this is for. An AWS access key is a password for your cloud account. If it ends up in a public place, like a GitHub repository, bots find it within minutes and start spending your money: big machines for crypto mining, usually in a region you have never opened. Then they make themselves a spare key, so that deleting the one you leaked does not lock them out. keyleak reads your own AWS logs and answers two questions: what did the attacker do, and what is still running. It never touches the stolen key, and it changes nothing unless you say so.

Seven questions, one command each. Run it, read what it prints, take the arrow down. The output is what keyleak really prints, from a simulated incident with made-up names.

Press enter, or tap the command line, to run the first one.

END OF TRANSMISSIONRun it yourself.

$ pipx install git+https://github.com/RedaKarrach/keyleak

# use your OWN login, never the leaked key
$ export AWS_PROFILE=my-admin

$ keyleak investigate AKIAIOSFODNN7EXAMPLE --home-region eu-west-1   # what did they do
$ keyleak sweep --since 2026-10-14                                    # what is still running
$ keyleak contain AKIAIOSFODNN7EXAMPLE --confirm                      # switch the key off
$ keyleak report --out incident.html                                  # report + message to AWS Support

# permissions for the read-only commands (ships in the repo)
docs/keyleak-readonly-policy.json: cloudtrail:LookupEvents, iam:Get*, iam:List*, ec2:Describe*, lambda:List*, sts:GetCallerIdentity

# what it cannot do
- CloudTrail event history only goes back 90 days.
- it sweeps EC2, Lambda and IAM. check the billing console for the rest.
- it does not clean up for you. deleting users and terminating machines is your call, on purpose.

# stack
Python 3.11+ · boto3 · click · rich · tests with botocore Stubber, no AWS account needed
