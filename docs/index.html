Step 1 · t+00:00

You push a commit.

A settings file with an access key in it. You were in a hurry. You do not notice, and nothing tells you.

Step 2 · t+00:04

A bot finds it in four minutes.

Bots read every public commit on GitHub looking for strings shaped like AKIA…. Then they try the key. It works.

Step 3 · t+00:05

The attacker looks around.

GetCallerIdentity: who am I. ListUsers: who else is here. Quiet, read-only, from an IP you have never seen.

Step 4 · t+00:07

They create a user called backup-svc.

A name chosen to look boring, so that nobody deletes it when they clean up later.

Step 5 · t+00:08

They give that user its own key.

This is the backdoor. It is not the key you leaked. It will keep working after you delete the key you leaked.

Step 6 · t+00:14

Eight GPU machines start in Singapore.

A region you have never opened, launched with the new key, not the leaked one. They mine cryptocurrency. You pay for the electricity.

Step 7 · day 3

The bill arrives.

Three days later, an email from AWS. This is usually the first moment you learn anything happened.

Step 8 · day 3, ten minutes later

You delete the leaked key. Nothing changes.

Every guide says "delete the key". You do. The user, the second key and the machines are untouched, because they were never tied to the key you deleted. This is where most people stop, and where the second bill comes from.

Step 9 · keyleak investigate

One command, run as yourself.

keyleak reads your own CloudTrail logs with your own login. The leaked key is only a search term. It finds the key, then follows what the key created, then what that created.

Step 10 · the pivot

All four, on one screen.

The leaked key, the user it made, the key that user got, and the machines that key launched. Each one found through the one before it. Now you can remove all of them, not only the first.

Step 11 · keyleak sweep, then contain

What is still running, and the one switch.

sweep lists what is still billing, in every region. contain turns off exactly one key, only with --confirm, and prints what it changed. Terminating the machines and deleting the user stays in your hands.

Step 12 · keyleak report

A report, and a refund request already written.

One HTML file with the timeline, what was running, what you did, and a message to AWS Support with the facts filled in. AWS often waives a first incident when you can show exactly this.

Get keyleak ↓

The end, and the start

Thirty seconds to run it.

Install and run

pipx install git+https://github.com/RedaKarrach/keyleak

export AWS_PROFILE=my-admin     # your own login, never the leaked key
keyleak investigate AKIAIOSFODNN7EXAMPLE --home-region eu-west-1
keyleak sweep --since 2026-10-14
keyleak contain AKIAIOSFODNN7EXAMPLE --confirm
keyleak report --out incident.html

Why it is safe to run while stressed

  • It never uses the leaked key, and refuses to start if your credentials are that key.
  • investigate, sweep and report change nothing. contain changes one key, with --confirm.
  • Nothing leaves your machine. No accounts, no telemetry.
  • A read-only IAM policy with the few permissions it needs ships in the repository.

What it cannot do

  • CloudTrail event history is 90 days; older activity is gone.
  • It sweeps EC2, Lambda and IAM. Check billing for the rest.
  • It is a first-response tool, not a forensic suite.

For developers

  • Python 3.11+, boto3, click, rich. MIT.
  • Tests use botocore Stubber; no AWS account needed. The attacker scenario on this page is the test fixture.
  • README: every option, the permissions, the limits.
  • DEMO.md: reproduce a real detection with Stratus Red Team in a throwaway account.
  • Read-only IAM policy.
